SECURITY
================================================================================

Sensitive Routes NOT Cached:
- /api/auth/* (authentication)
- /api/payments/* (payment data)
- /api/users (personal data)
- /api/admin/* (admin operations)
- /api/verification/* (verification tokens)
- /api/subscriptions/* (subscription changes)

Per-User Cache Keys:
- Cache keys include user ID when authenticated
- Same user gets their data
- Different users get different cache entries

No Credentials in Cache:
- Redis connection string in .env (not committed)
- Credentials never logged
- SSL/TLS support via REDIS_URL

================================================================================
TROUBLESHOOTING
================================================================================

Issue: Cache not working
→ Check health endpoint: /api/health
→ Verify X-Cache header present
→ Check logs for [Cache] messages

Issue: Stale data after update
→ Invalidation pattern too narrow
→ Make pattern broader (professional:* not professional:123:avatar)

Issue: High memory usage
→ Check Redis memory: redis-cli info memory
→ Review TTLs in cacheMiddleware.js
→ Scale Redis or reduce TTLs

Issue: Redis unavailable
→ Automatic fallback to in-memory cache
→ Check health endpoint
→ Restart Redis or configure new REDIS_URL

Full troubleshooting in /CACHE_INTEGRATION_GUIDE.md
