================================================================================
ROOM STRATEGY
================================================================================

Room Naming Convention:
  user:{userId}                  - Personal updates (1 user)
  booking:{bookingId}            - Booking room (2 users: client + pro)
  conversation:{conversationId}  - Chat room (2+ users)
  notifications:{userId}         - Notification room (1 user)
  presence:global                - Global presence (all users)
  payment:{paymentId}            - Payment tracking (1+ users)

Broadcast Strategy:
  - Targeted rooms minimize message overhead
  - Role-based access control on join
  - Client-side subscription for flexibility
  - Server-side validation on emit

USAGE QUICK START
================================================================================

1. CLIENT CONNECT
   import { io } from 'socket.io-client';
   const socket = io('http://localhost:4000', {
     auth: { token: jwtToken }
   });

2. SUBSCRIBE TO ROOMS
   socket.emit('subscribe:booking', { bookingId: 'id-123' });
   socket.emit('subscribe:conversation', { conversationId: 'id-456' });

3. LISTEN TO EVENTS
   socket.on('booking.update', (data) => { });
   socket.on('message.new', (data) => { });

4. SEND EVENTS
   socket.emit('message.new', { conversationId, text });
   socket.emit('message.typing', { conversationId, isTyping: true });

5. SERVER SIDE (in routes)
   const io = req.app.get('io');
   io.to('booking:' + id).emit('booking.update', data);
